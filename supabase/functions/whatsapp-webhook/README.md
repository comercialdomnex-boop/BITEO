# BITEO — Meta WhatsApp webhook (development only)

This Edge Function is **not deployed**. The Meta callback URL cannot be entered until the function is publicly deployed.

## Security

- GET `hub.mode=subscribe`, `hub.verify_token` and `hub.challenge` verifies Meta ownership.
- POST requires `X-Hub-Signature-256` HMAC-SHA256 computed over the exact raw request body using `META_APP_SECRET`.
- Only status events with a matching connected store's `waba_id` and `phone_number_id` and a matching outbox `meta_message_id` are updated.
- No browser-accessible credentials, no unauthenticated database write API.
- No inbound customer-message processing, outbound sending, OAuth signup, token storage, or checkout consent has been implemented yet.
- Status webhooks that arrive before the outbound worker stores the Meta message ID will be ignored. A later iteration should reconcile early webhook events.

## Required server secrets (do not commit values)

- `META_WHATSAPP_VERIFY_TOKEN`: random token generated by the platform and also configured in the Meta webhook form.
- `META_APP_SECRET`: Meta App Secret; used to verify POST signatures.
- `SUPABASE_URL`: Supabase project URL.
- `SUPABASE_SERVICE_ROLE_KEY`: server-only privileged key.

## Manual local validation checklist

1. Review and test the migration `20261030180000_whatsapp_cloud_foundation.sql` on an isolated development database before any production application. It is **not** deployed.
2. Use `supabase functions serve whatsapp-webhook --no-verify-jwt --env-file <local-secrets-file>` for local tests. Keep the secrets file outside Git.
3. GET with the correct `hub.verify_token` returns the exact `hub.challenge` text and HTTP 200. Wrong token returns 403.
4. POST with no signature, wrong signature, or modified body returns 401.
5. A correctly signed unrelated payload returns 200 without changing records.
6. A signed status update should change only the outbox record matching the connected store, WABA, phone ID and Meta message ID. Verify a mismatched tenant remains unchanged.
7. Verify duplicate and out-of-order notifications do not downgrade delivered/read statuses.
8. Confirm database errors produce HTTP 500 so Meta can retry.

## Future deployment (requires explicit approval)

The webhook is called by Meta without a Supabase JWT, so it must be deployed with `--no-verify-jwt`. **Never** disable the HMAC signature validation. Only after the function is deployed and secrets are configured, enter the resulting callback URL and the verification token in the Meta Developer dashboard.

Before production: implement verified Meta Embedded Signup for each merchant, secure credential storage, consent capture, outbound worker, approved templates, delivery retries, and audit logging. Review Meta webhook subscription and app publication requirements.
